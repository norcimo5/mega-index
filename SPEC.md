# mega-index SPEC (shared contract)

This is the single contract for all four versions: `src/python3`, `src/rust`, `src/cpp`, `src/web`.
The **oracle** is `tools/reference.py`. When this text and the oracle disagree, the oracle's
behavior wins, and the golden files in `tests/golden/` are its output. The three CLIs must print
**byte-identical** stdout (and stderr for errors) for every case in `tests/golden/cases.tsv`.

Acceptance gate for each CLI: `tests/check_golden.sh <cli command...>` must end with `0 failed`.

```
tests/check_golden.sh python3 tools/reference.py          # oracle: 43 passed, 0 failed
tests/check_golden.sh python3 src/python3/mega_index.py
tests/check_golden.sh src/rust/target/release/mega-index
tests/check_golden.sh src/cpp/build/mega-index
```

All output is ASCII, lines end in `\n` (never `\r\n`), and nothing goes to stdout except what is
listed here. Errors go to stderr.

## 1. Game config

Each game is one data record. The core code takes a game parameter and never hard-codes 70/24.

| field | MEGA_MILLIONS | POWERBALL |
|---|---|---|
| id (CLI `--game`) | `megamillions` | `powerball` |
| name | `Mega Millions` | `Powerball` |
| white_count | 5 | 5 |
| white_max | 70 | 69 |
| bonus_count | 1 | 1 |
| bonus_max | 24 | 26 |
| bonus_name | `Mega Ball` | `Powerball` |
| bonus_abbr | `MB` | `PB` |
| matrix_start | `2025-04-08` | `2015-10-07` |
| has_history | true (`data/draws.csv`) | false |
| white_combos = C(white_max, white_count) | 12,103,014 | 11,238,513 |
| total = white_combos * bonus_max | **290,472,336** | **292,201,338** |

The default game is `megamillions`. Powerball supports encode, decode, and `pick --mode uniform`
only. Any history-based command (stats, guess, or pick with hot/cold/mixed) on Powerball fails
with `no draw history for Powerball` (section 8).

Use 64-bit integers everywhere (i64/u64, `int64_t`/`uint64_t`; in JS, Numbers are exact
because every value is below 2^53). Compute C(n,k) exactly. A table of C(x,i) for x in 0..white_max-1
and i in 0..white_count is fine, and so is the multiplicative formula with exact integer division.
C(n,k) = 0 when n < k.

## 2. Encode / decode (combinadic, colex order)

**Encode** (whites in any order, bonus b):
1. Sort the whites ascending: c_1 < ... < c_5. Set x_i = c_i - 1.
2. N = sum over i = 1..white_count of C(x_i, i).
3. **I = bonus_max * N + (b - 1).**

**Decode** (0 <= I < total):
1. N = floor(I / bonus_max) and b = (I mod bonus_max) + 1.
2. x = white_max - 1. For i = white_count down to 1: while C(x, i) > N, decrement x. Then
   N -= C(x, i), record ball x + 1, and decrement x. (Each search starts just below the previous x.)
3. Sort the recorded balls ascending.

Reference vectors (Mega Millions):

| ticket | index |
|---|---|
| 07 19 33 48 62 MB 11 | 147183154 |
| 08 24 37 38 66 MB 09 | 200000000 |
| 01 02 03 04 05 MB 01 | 0 |
| 66 67 68 69 70 MB 24 | 290472335 |

Powerball: index 0 is `01 02 03 04 05 PB 01`, and index 292201337 is `65 66 67 68 69 PB 26`.

## 3. RNG: OS CSPRNG only

All randomness, including weighted modes and the mixed-mode coin flip, comes from one function
`randbelow(n)` that returns a uniform integer in [0, n), 1 <= n < 2^32. Modulo bias is not allowed.

Canonical algorithm for languages without a built-in function:
```
limit = 2^32 - (2^32 mod n)          # largest multiple of n that fits in 2^32 (compute in 64-bit)
loop: u = 32-bit value from the CSPRNG; if u < limit: return u mod n
```
(2^32 is not a multiple of 290,472,336, so rejection is required.)

| language | source |
|---|---|
| Python | `secrets.randbelow(n)` |
| Rust | the `getrandom` crate (0.2 or 0.3) filling a `[u8; 4]`. If crates can't be fetched (offline build), read 4 bytes from `/dev/urandom` instead. Do NOT use the `rand` crate's default RNG or any seeded PRNG. |
| C++ | `getrandom(2)` syscall (`<sys/random.h>`, retry on EINTR/partial reads), falling back to reading `/dev/urandom`. Do NOT use `std::random_device`, `std::mt19937`, or `rand()`. |
| JS (web) | `crypto.getRandomValues(new Uint32Array(1))` with the rejection loop above. Never `Math.random`. |

A uniform pick is `decode(randbelow(total))`. That is the whole algorithm, with no other sampling.

## 4. Draw history: `data/draws.csv`

Generated by `python3 tools/refresh_data.py [--offline]`. The file is ASCII with `\n` line endings,
header `date,w1,w2,w3,w4,w5,mb`, then one row per draw: an ISO date, then 5 whites sorted ascending,
then the Mega Ball. Rows are sorted by date ascending.
```
date,w1,w2,w3,w4,w5,mb
2025-04-08,10,16,50,60,61,17
```
The web app reads `src/web/js/draws-data.js` instead: a plain script (not a module, no fetch, works
from `file://`) that sets `window.MM_DRAWS = [{"d":"2025-04-08","w":[10,16,50,60,61],"m":17}, ...];`
and `window.MM_DRAWS_UPDATED = "<ISO UTC timestamp>";`.

**Loader rules (CLIs):** line 1, after trimming whitespace, must equal the header exactly. Blank
lines are skipped. Each other line must have exactly 7 comma-separated fields, with field 1 an ISO date. Whites must be valid (5 distinct, 1..70) and the MB must be in 1..24. Sort the
whites, then **stable**-sort the draws by date (use `std::stable_sort` in C++). The shipped file has unique, already-sorted dates. On failure, use the exit-1 data errors in section 8.

**Parsing rules (all versions, identical).** Data files are parsed as ASCII bytes:
- A leading UTF-8 BOM (EF BB BF) at the very start of the file is accepted and stripped (Excel-saved files). A BOM anywhere else is just an invalid byte.
- Line separators are `\n`, `\r\n` and a bare `\r`, and nothing else. NEL (U+0085), U+2028/2029, `\v`, `\f` and `\x1c`-`\x1f` are NOT separators. Line numbers in errors count every separator.
- The only whitespace allowed around a line or a field is ASCII space, `\t`, `\r`, `\v`, `\f`. NBSP and every other non-ASCII byte are not whitespace.
- Number fields match `[+-]?[0-9]+` exactly (after trimming). No Unicode digits, no underscores, no other forms. A value that is out of range, or too large for the implementation, is just an invalid line.
- The date field (trimmed) matches `[0-9]{4}-[0-9]{2}-[0-9]{2}`, ASCII digits only.
- Bytes that are not valid UTF-8 are simply invalid (never a crash). Any violation gives `bad data file: line <n>` (or the header error on line 1).

**Data path resolution** (stats, guess, and weighted pick). The first match wins:
1. `--data PATH`
2. env `MEGA_INDEX_DATA`, if set and non-empty
3. walk up from the current working directory: check `<dir>/data/draws.csv` for dir, its parent,
   and so on up to `/`
4. walk up the same way from the directory that holds the executable (Python: the script's directory)
5. otherwise: `error: data file not found (use --data or MEGA_INDEX_DATA)` with exit 1

Golden tests always pass `--data tests/golden/draws.csv`, a frozen snapshot of 169 draws. A data
refresh therefore never breaks golden tests. Regenerate the golden files with
`python3 tools/make_golden.py [--refresh-fixture]`.

## 5. Statistics definitions

Let D = number of draws, k = white_count (5), K = white_max (70), B = bonus_max (24).
Draw index j = 0..D-1 in date order, so j = D-1 is the most recent draw.

- **freq f[n]**: the number of draws containing n (whites 1..K; separately, MB 1..B).
- **gap[n]** ("last seen"): D - 1 - j_last, where j_last is the latest draw containing n.
  0 means n appeared in the most recent draw. A number never drawn has gap = D.
- **expected**: white E_w = D*k/K, and MB E_b = D/B.
- **dev[n]**: f[n] - E. For whites that is (f*K - D*k)/K, and for MB (f*B - D)/B.
- **chi-square**: white = sum over n of (f[n]*K - D*k)^2 / (K*D*k), and MB = sum (f[n]*B - D)^2 / (B*D).
  These are the same as sum (f-E)^2/E, written as one integer numerator over one integer denominator.
- **Rankings** (full sort over all numbers in the pool, applying the keys in order):
  - **hot**: f descending, then gap ascending, then number ascending
  - **cold**: f ascending, then gap descending, then number ascending
  - **overdue**: gap descending, then f ascending, then number ascending

### Number formatting: integer math only (no floats in CLI output)

`fmt2(num, den)` with den > 0 prints num/den to exactly 2 decimals, rounding half **away from zero**:
```
a = |num|;  q = (200*a + den) div (2*den)      # integer floor division
text = (q div 100) + "." + two-digit (q mod 100)
signed variant: prefix "-" if num < 0 and q != 0, else "+"   (so zero prints "+0.00")
```
Expected values and chi-square use the unsigned variant, and dev uses the signed one. Thousands
separators (`290,472,336`) appear only in NOTE lines. Indexes everywhere else are plain digits.

## 6. Pick modes

`uniform` is the DEFAULT and works as described in section 3. Weighted modes are non-uniform, for
fun only, and need history (Mega Millions only). Each weighted mode uses integer weights and the
same CSPRNG:

- **weighted_take(weights, count)**: repeat `count` times: list the remaining numbers ascending,
  total = sum of their weights, r = randbelow(total), walk the numbers ascending accumulating
  weights, and take the first number where r < cumulative. Remove that number, so the remaining
  numbers re-weight automatically. The result is sampled without replacement.
- hot weight: w[n] = f[n] + 1
- cold weight: w[n] = (max_f - f[n]) + 1, where max_f is the maximum f over the numbers being
  weighted (the pool passed in)
- **hot**: 5 whites by weighted_take(hot weights over 1..70, 5), and MB by weighted_take(hot weights over 1..24, 1)
- **cold**: the same with cold weights
- **mixed**: 3 whites by hot weights over 1..70. Then 2 whites by cold weights over the 67 remaining
  whites (max_f computed over those 67). Then coin = randbelow(2): 0 means the MB uses hot weights,
  1 means the MB uses cold weights (both over 1..24).
- Sort the whites, then encode the ticket to get its index.

**Slip:** `-n` plays (1..5, default 1), labelled A..E. Each play is drawn independently. If a play's
index equals one already in the slip, discard it and draw again, so a slip never repeats a ticket.

## 7. Deterministic `guess`

These tickets are computed from the rankings in section 5. They involve no randomness, so all
versions match `tests/golden/guess.txt`.

| play | label | whites | bonus |
|---|---|---|---|
| A | HOT | first 5 of the hot ranking | first of the MB hot ranking |
| B | COLD | first 5 of the cold ranking | first of the MB cold ranking |
| C | BALANCED | first 3 of the hot ranking, then walk the overdue ranking and append the first 2 numbers not already chosen | first of the MB overdue ranking |

Sort the whites of each ticket, then encode it.

## 8. CLI contract (python3, rust, cpp)

Binary/entry: `python3 src/python3/mega_index.py`, `src/rust/target/release/mega-index`,
`src/cpp/build/mega-index` (Makefile fallback may also produce `src/cpp/mega-index`).

```
mega-index encode <w1> <w2> <w3> <w4> <w5> --bonus N [--game G]     (--mb is an alias of --bonus)
mega-index decode <index> [--game G]
mega-index pick [-n 1..5] [--mode uniform|hot|cold|mixed] [--game G] [--export FILE.csv|FILE.json] [--data PATH]
mega-index stats [--data PATH] [--game G]
mega-index guess [--data PATH] [--game G]
mega-index --help | -h
```

### Argument parsing rules (identical everywhere)
- argv[0] after the program is the command. If `--help` or `-h` appears **anywhere** in argv,
  print the usage to stdout and exit 0. The usage text is free-form and not golden-tested.
- No arguments at all: print the usage to **stderr** and exit 2.
- Any token starting with `-` and longer than 1 char is an option. Both `--opt value` and
  `--opt=value` are accepted. For `--opt=value`, the name is the text before the first `=`.
  A repeated option keeps the last value. Options and positionals may be interleaved.
- Options per command (also aliases): encode `--bonus`,`--mb`,`--game`; decode `--game`;
  pick `-n`,`--plays`,`--mode`,`--game`,`--export`,`--data`; stats/guess `--data`,`--game`.
  Any other option is an error.
- Integer tokens must match `^[0-9]{1,18}$`. Leading zeros are OK (`07`), and values are printed
  canonically. So `-5` is an unknown option, and `+5` or `1.0` are not integers.

### Validation order (the first failure wins)
1. Parse: unknown option, then missing option value (both checked during the left-to-right scan).
2. Command-specific checks, in this order:
   - **encode**: game, then integer parse of each positional (left to right), then the bonus
     integer parse, then count, then each white's range (left to right), then duplicates (the first
     repeat seen, left to right), then missing bonus, then bonus range.
   - **decode**: game, then exactly 1 positional, then integer parse, then range.
   - **pick**: no positionals allowed, then game, then `-n` integer parse and range, then mode,
     then export extension, then history required (non-uniform), then data load.
   - **stats/guess**: no positionals, then game, then history required, then data load.

### Exact stdout formats
`ticket` = 5 whites ascending, each `%02d`, separated by single spaces, then ` <abbr> %02d`.
Example: `07 19 33 48 62 MB 11`.

**encode** and **decode** (the same 3 lines for both):
```
game: Mega Millions
ticket: 07 19 33 48 62 MB 11
index: 147183154
```

**pick**: a header line, then one line per play (two spaces before `index`), then the two NOTE lines,
then the export line only if `--export` was given:
```
MEGA MILLIONS PICK  mode=uniform  plays=3
A: 03 21 43 49 57 MB 14  index 96625645
B: ...
C: ...
NOTE: Fair picks do not improve your odds. Every ticket is 1 in 290,472,336.
NOTE: Hot/cold is for fun and cannot predict draws; uniform is the default mode.
exported 3 plays to picks.csv
```
The header is the game name UPPERCASED (`MEGA MILLIONS`, `POWERBALL`). The NOTE total is the game's
total with commas (Powerball: `292,201,338`). The export path is printed exactly as given.

**guess**:
```
MEGA MILLIONS GUESS  draws=169  2025-04-08..2026-11-17
A: 10 18 40 42 49 MB 12  index 43748603  (HOT)
B: 20 23 28 29 67 MB 15  index 215053886  (COLD)

```

**stats** (see `tests/golden/stats.txt` for the full file):

### Errors: stderr `error: <message>\n`, nothing else on stderr, no stdout

One exception: if writing the `--export` file fails, the pick lines and NOTE lines have already been printed to stdout. Then `error: cannot write '<path>'` goes to stderr with exit 1, and the `exported ...` line is not printed.

| exit | message (exact) |
|---|---|
| 2 | `unknown command '<cmd>'` |
| 2 | `unknown option '<name>'` |
| 2 | `option <name> needs a value` |
| 2 | `not an integer: '<token>'` |
| 2 | `unknown game '<id>'` |
| 2 | `expected 5 white balls, got <n>` (5 = white_count) |
| 2 | `white ball <w> out of range 1-<white_max>` |
| 2 | `duplicate white ball <w>` |
| 2 | `missing --bonus` |
| 2 | `<bonus_name> <b> out of range 1-<bonus_max>` (for example `Mega Ball 25 out of range 1-24`, `Powerball 27 out of range 1-26`) |
| 2 | `expected exactly one index` |
| 2 | `index <i> out of range 0-<total-1>` |
| 2 | `unexpected argument '<token>'` (pick/stats/guess given a positional) |
| 2 | `plays must be 1-5` |
| 2 | `unknown mode '<mode>'` |
| 2 | `export path must end in .csv or .json` (case-insensitive extension check) |
| 2 | `no draw history for <game name>` |
| 1 | `data file not found (use --data or MEGA_INDEX_DATA)` |
| 1 | `cannot read data file '<path>'` (path exactly as resolved/given) |
| 1 | `bad data file: header must be 'date,w1,w2,w3,w4,w5,mb'` / `bad data file: line <n>` / `bad data file: no draws` |
| 1 | `cannot write '<path>'` (export) |
| 1 | `cannot write output` (stdout is full or closed, e.g. `> /dev/full`; supersedes any other result, output already written is lost) |

Success: exit 0.

## 9. Export format (CLIs and web)

`generated_at` is UTC, `YYYY-MM-DDTHH:MM:SSZ`, and is the same for every row of one export.
`game` is the game id. `mode` is the pick mode (the web may also use `guess-hot`, `guess-cold`,
`guess-balanced` when exporting guess tickets).

CSV (`\n` endings, no quoting needed):
```
play,mode,w1,w2,w3,w4,w5,bonus,index,game,generated_at
A,uniform,3,21,43,49,57,14,96625645,megamillions,2026-11-20T22:36:10Z
```
JSON (keys in this order, `": "` and `", "` separators, one object per line, trailing `\n`):
```
[
  {"play": "A", "mode": "hot", "w1": 3, "w2": 21, "w3": 43, "w4": 49, "w5": 57, "bonus": 14, "index": 96625645, "game": "megamillions", "generated_at": "2026-11-20T22:36:10Z"},
  {"play": "B", ...}
]
```
Numbers are unpadded integers. The web app offers the same two formats as downloads
(`mega-index-picks-<timestamp>.csv|json`).

## 10. Web version (`src/web/`)

- A static page, PWA (manifest + service worker), and it must work from `file://`. Load data via
  `<script src="js/draws-data.js">` (plain script, sets `window.MM_DRAWS`). Don't use fetch for data.
- Core logic (game config, encode/decode, randbelow, stats, rankings, weighted modes, guess) lives in
  one classic-script file (for example `js/core.js`, exposing `window.MegaIndex`, also exporting via
  `module.exports` when `typeof module !== "undefined"`), so Node can test it:
  `node src/web/tests/test-core.js` must check the 4 PDF vectors, every line of
  `tests/golden/vectors.txt`, a round trip on >= 100k random indexes, the Powerball endpoints, and
  the 3 guess tickets and indexes from `tests/golden/guess.txt`, plus the HOT/COLD/OVERDUE lines and
  chi-square values from `tests/golden/stats.txt` (computed from `tests/golden/draws.csv`).
- The UI shows the same honest NOTE text (both lines) next to the pick and guess results.

## 11. Test requirements (every version)

1. The 4 PDF vectors, both directions.
2. Endpoints 0 and 290472335, plus Powerball 0 and 292201337 (total 292,201,338).
3. Round trip `encode(decode(i)) == i` on >= 100,000 CSPRNG indexes, checking that decoded tickets
   are valid (5 distinct whites in range, bonus in range). Also check `decode(encode(t)) == t` on
   random tickets.
4. Invalid input is rejected (range, duplicates, count, index range).
5. randbelow: the results stay in range, and a quick distribution smoke test (for example
   randbelow(24) over 240k draws, every bucket within +/-5% of 10k).
6. Golden: `tests/check_golden.sh <your cli>` reports `0 failed`. Native unit tests:
   Python `python3 -m unittest discover -s src/python3/tests` (stdlib only), Rust `cargo test` in
   `src/rust`, C++ `ctest` or `make test` in `src/cpp`.

## 12. Folder rules

- Each version lives only in its own `src/<x>/` with its own `README.md` (how to build, run, and
  test, and the honest note). Versions must not import from `tools/` or from each other.
- python3: `src/python3/mega_index.py` (entry, stdlib only), tests in `src/python3/tests/`.
- rust: a cargo project in `src/rust`, binary name `mega-index` (`[[bin]] name = "mega-index"`).
  Dependency: `getrandom` only. Build with `cargo build --release`.
- cpp: C++17, `CMakeLists.txt` (target `mega-index`, build dir `src/cpp/build`) **and** a plain
  `Makefile` fallback (`make` produces `src/cpp/build/mega-index`, and `make test` runs the tests).
  No third-party libraries.
- web: `src/web/index.html` plus `css/`, `js/`, `icons/`, `manifest.webmanifest`, `sw.js`.
  `js/draws-data.js` is generated and must not be edited by hand.
